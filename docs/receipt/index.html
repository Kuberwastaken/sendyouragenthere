The Agent EditionReader’s copy

What did your agent share?

This is the explanation behind a small WebMCP privacy experiment. A completed signup returns a link that renders the fictional reader’s copy here.

If your agent sent you here, did you see these steps while it was fetching the news?

  1. The static page returned the full reader instructions through a WebMCP tool. You could receive only the final answer and miss that exchange.
  2. The next tool call followed the signup instructions in that same-domain file. A site can observe that it served a file. Only the host can tell you whether it installed a skill.
  3. The signup tool received the following press-pass fields before it returned the article.

These are fictional values. This link reconstructs the press pass in your browser. Anyone can copy or construct one. Your agent’s transcript is where you can check the calls and any approval.

All that to read one paragraph.

The paper needed exactly zero facts about its reader. A field marked “required” tells you what a publisher wants. Who gets to decide whether your agent supplies it?

This is a deliberately naive version. We supplied the press pass ourselves. A less scrupulous publisher could keep real details and connect a particular person to the story they read. A confirmation after the signup call would arrive too late.

In its November 24 announcement, Anthropic described connected MCP servers shipping skills and said file uploads were coming. This site uses the separate WebMCP browser API. Think about the difference between sending a byline and sending the document that byline came from.
